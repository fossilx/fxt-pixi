# Sampler goals

The sampler picks the moments worth examining, and in a trading system those are your candidate entry points. In ML terms it does a second job too, and that one matters for how the rest of the system fits together.

**It decides which rows exist in the training data.** Every event becomes one example. It gets a label (what happened after), features (what the market looked like at `t0`), and a weight. Bars that never fire an event are never labeled and never learned from. So the sampler doesn't only find entries: it defines the population the model learns about and is later asked about.

That has three consequences:

- **The model only judges moments the sampler picked.** The meta-model learns "given that CUSUM fired, is this one worth taking?", not "is now a good time to trade?". Asked about an arbitrary bar, its answers mean nothing, because it never saw arbitrary bars in training. In live trading it must be fed by the exact same sampler with the same config hash.
- **The sampler is tuned for recall, not precision.** It should catch most real opportunities and accept plenty of false alarms, because filtering those out is the meta-model's job. A sampler that's too picky leaves the meta-model too few examples. One that fires on nearly every bar brings back the problem it exists to solve: overlapping, near-identical examples that teach little.
- **It's a statistical choice, not just a trading one.** Consecutive hourly bars are heavily correlated, so a model trained on every bar mostly memorizes noise. Sampling on "something unusual just happened" gives fewer, more informative, less redundant examples. This is why CUSUM is a common default.

**One distinction from your description:** the sampler says *when*, not *which way*. In the current design, an event has a raw `direction` (which way the CUSUM fired), but no trade side. The side rule turns that into long or short, so the same events can be tested as momentum (`follow`) or mean reversion (`fade`).

The whole chain, one question per stage:

| stage | question it answers | output |
|---|---|---|
| features | what did the market look like at each bar close? | per-bar values, independent of any strategy |
| sampler | when is something worth looking at? | events (`t0`, `direction`) |
| side rule | which way would we trade it? | `side` per event |
| labels | what happened after we would have entered? | outcome, return, `meta_label` |
| weights | how much should each example count, given overlap? | weight per event |
| meta-model | is this particular event likely to work? | probability |
| sizing | how much to commit, given that probability? | position size |
| exits | how is the open trade managed? | exit policy |

The sampler and side rule together are "System 1", the strategy. Swapping either one gives you a new strategy, and everything below it is reused unchanged.
